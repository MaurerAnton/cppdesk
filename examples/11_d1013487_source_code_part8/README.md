## Bugs caught during this step (both fixed in-step)

1. **Extraction bug**: the generator collapsed Rust `'\\''` (apostrophe) to
   backslash — `VK_QUOTE` initially mapped to `'\\'`. Fixed to `'\''`; the
   step README documents the pitfall for future regenerations.
2. **Stale API call**: first draft called `config_.store(id)` — `PeerConfig`
   is a plain struct here, persistence is `peer_store(cfg, id)`. Compiler
   caught it.

## KEY_MAP regeneration (if upstream edits the table)

Extract from `src/client.rs` at the upstream commit:

```console
$ git -C <rustdesk-checkout> show d1013487:src/client.rs > /tmp/client.rs
$ python3 extract_keymap.py /tmp/client.rs \
    libs/hbb_common/protos/gen/message.pb.h > src/key_map.cpp
```

Rules for the extractor (learned the hard way in this step):
- match `("NAME", Key::Chr('c' as _))` and `("NAME", Key::ControlKey(ControlKey::K))`
  pairs **in source order**;
- assert every `ControlKey::K` exists as a flat enumerator in the generated
  `message.pb.h` before emitting;
- parse Rust char literals properly: `'\''` is APOSTROPHE, `'\\'` is backslash —
  do NOT strip surrounding quotes naively (that was the VK_QUOTE bug);
- emit C++ escapes (`'\''`, `'\\'`) accordingly;
- keep duplicate keys with a comment (first wins in both `HashMap` and
  `unordered_map`, same observable map).
